# Sēn — Pilot Operating Playbook V1

## Purpose
Run the first Sēn cohort as a controlled operating experiment, not a launch celebration.

## Cohort ladder
1. Concierge: 5–10 invited users
2. Founding 25
3. 25 → 50
4. 50 → 100

No cohort graduates automatically.

## Graduation gates
All must be acceptable:
- booking success
- partner reliability
- repeat use
- support load
- contribution margin
- refund/reconciliation accuracy
- zero unresolved critical safety/privacy issues

## Concierge pilot
Goal: discover operational failure modes with very few users.

Founder/ops manually:
- recommends options
- verifies inventory
- confirms bookings
- handles support
- reconciles partner usage
- logs issues
- interviews users after use

Do not automate pain before understanding it.

## Founding 25
Start only when:
- at least 15 strong partners are operationally plausible
- core booking flow is understandable
- refund/cancellation paths are tested
- incident owner exists
- basic ledger/reconciliation exists
- founder can support the cohort without chaos

## Daily cadence
08:00 — partner/inventory health
11:00 — payment and booking exceptions
15:00 — support and waitlists
20:30 — incident reconciliation
Friday — unit economics, partner economics, member feedback, go/pause review

## Member issue handling
Priority:
1. Protect safety/trust
2. Restore member state
3. Explain clearly
4. Reconcile money/benefit
5. Investigate partner/system
6. Prevent recurrence

## Partner issue handling
Track:
- partner cancellation
- booking not recognized
- overbooking
- closed venue
- poor staff interaction
- capacity mismatch
- repeated check-in failure
- payout discrepancy

## Manual tools allowed
- spreadsheet / lightweight database
- WhatsApp/email for partner coordination
- simple admin dashboard
- manual payout review
- founder concierge

Manual is acceptable if:
- member experience remains coherent
- data is logged
- workflow is repeatable
- risk is bounded

## Scale stop conditions
Pause growth if:
- partner cancellation rises materially
- refund backlog grows
- support exceeds sustainable capacity
- contribution margin collapses
- serious safety/privacy incident unresolved
- repeat use does not appear
- users value only one subsidized category

## Pilot output
At 100 members we should know:
- strongest acquisition channel
- strongest retention behavior
- true category mix
- real heavy-user behavior
- partner payout reality
- support cost
- AI value
- whether Circles create offline action
- which workflow deserves automation next
