# Sēn — Adaptive Intelligence & Growth Direction V3

## Principle
Sēn should continuously learn, but never silently trap the user inside an old profile.

## Conversational consultation
After onboarding, Sēn gradually learns through:
- explicit conversation
- choices
- skips
- bookings
- cancellations
- time-of-day patterns
- optional location context
- stated preferences
- explicit edits

It should feel like an ongoing consultation, not a one-time quiz.

## Editable memory
Users can access "What Sēn remembers" and:
- edit
- disable
- remove
- reset

Preferences decay or change when behavior changes.

Example:
Month 1: boxing high relevance
Month 3: user stops engaging with boxing and repeatedly chooses Pilates
Result: Pilates rises; boxing decays unless the user pins it.

## Location intelligence
Location is opt-in and revocable.

Examples:
- "You're near Asa Sul. A boxing class starts at 16:30, 12 minutes away."
- "You're leaving work earlier than usual. Want something light nearby?"

Rules:
- explain why suggestion appeared
- avoid constant tracking unless necessary and consented
- allow pause/disable
- never expose exact location socially

## Membership growth
Membership should be promoted contextually through:
- visible savings
- access gaps
- privileges
- recurring usage
- personalized recommendations
- transparent promotional campaigns

## Offers
Avoid opaque individualized pricing.

Preferred:
- campaign-based offers
- clearly labeled eligibility
- capped discounts
- transparent duration/terms
- fairness monitoring

Example:
"7% off Core for your first 3 months — active-use campaign."

Do not secretly charge different users different base prices because an AI predicts willingness to pay.

## Continuous product evolution
Sēn should operate as a learning system:
Observe → hypothesize → test → measure → keep/change/remove.

Every major feature should have:
- hypothesis
- metric
- experiment
- review date
- kill/change criteria

Goal: continuous improvement without product chaos.
